# Three-minute demo

All five team members can rehearse and record this phase together. Use a new private demo workspace so the five-video task is unused. Keep the simulation label visible and never present simulated receipts as PayPal receipts.

| Time | Show | Say |
| --- | --- | --- |
| 0:00–0:25 | Landing page | An agent asked to create five videos could submit hundreds of operations. Giving it the main account makes mistakes expensive. AgentVault gives it a defined spending boundary. |
| 0:25–0:55 | Permissions | Choose permitted payees, a maximum payment, daily and monthly limits, an expiry date and when approval is required. These rules run in the backend. |
| 0:55–1:30 | Electricity request → approve → simulated checkout → confirm | This request needs owner approval. Approval is checked again before checkout and capture. The activity record shows what happened. This sequence is a simulation. |
| 1:30–2:00 | Settings → five-video control test | Five hundred proposals still share one task allowance. Only five operations can reserve funds. A new IP does not create a new budget. |
| 2:00–2:25 | Pause all agents → activity | The owner can stop new actions. Previously dispatched provider payments still need reconciliation. |
| 2:25–3:00 | Integration settings and security model | PayPal Sandbox is the first integration. The AI selects authorized tasks; deterministic rules enforce authority. The current vault is a virtual allowance. Provider-enforced funded isolation and broader service support are next. |

If sandbox credentials have been verified, record a separate real Sandbox create → buyer approval → capture sequence and show its provider IDs. Do not claim live-money custody, universal acceptance, existing-autopay discovery or passkey authentication. Record the actual app, narration and captions; this document is a script, not a finished video.
